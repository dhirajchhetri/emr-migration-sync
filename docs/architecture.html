What this flow does

Keeps a partner EMR and the wound care EMR in step, and migrates a new facility's history, through one anti-corruption path. Admissions and care summaries come as HL7 v2 through Redox; prescriptions and medication history come as NCPDP SCRIPT through Surescripts.

Key steps

  1. EMR system A sends HL7 v2 ADT (A01/A03/A08) and ORU results.
  2. The integration engine delivers them to the ingest API. The e-prescribing gateway delivers NewRx, CancelRx, RxFill, renewal, and medication history.
  3. The ingest API stores the raw payload, records an idempotency key, and queues a pointer per patient (SQS FIFO).
  4. Every payload lands in S3 raw. A legacy extract or a change log lands in the same zone.
  5. Glue ETL checks codes and dates and writes accepted rows to curated storage and failures to quarantine.
  6. A rules scorer matches patients. Uncertain matches go to a review queue and are not merged.
  7. A Step Functions job reconciles counts and checksums per entity.
  8. Translated records update EMR system B.

AWS services

API Gateway, Lambda, SQS FIFO, S3 (raw, curated, quarantine, reports), Glue ETL, Step Functions, DynamoDB (idempotency, audit, clinical documents, reviews), CloudWatch, IAM, KMS.

External systems

Partner EMRs (for example a skilled nursing facility system), Redox, Surescripts network.
